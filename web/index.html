              Teaching
            
          
      
          
      
            
      
              
                The task
              
              
      
                Given a public key and an encapsulation, recover the complete shared key. No candidate key or decapsulation oracle is supplied.
              
      
            
      
            
      
              
                The clock
              
              
      
                Everyone shares the same hourly round. Your answer must reach the server before the round ends. Requesting an instance later does not extend the deadline.
              
      
            
      
          
      
          
      
            
              Construction and parameters
              
                +
              
            
            
      The selected protocol defines its key generation, encapsulation, and decapsulation algorithms.
      
            
      
            
      
            
      
            
      
              Shared-key output length is independent of challenge tier; it does not measure security strength.
            
      
            
                  
      
            
      
              
                Download the reference implementation ↓
              
              ·
              
                Download the teaching solver ↓
              
            
      
            
      
              The example solver is provided for this deliberately weak teaching construction.
            
      
          
      
          
      
            
              Correctness
              
                +
              
            
            
      
            
      
            
      
              Correctness describes agreement between honest encapsulation and decapsulation. It does not establish resistance to an attack.
            
      
          
      
          
      
            
              What a result establishes
              
                +
              
            
            
      
              A correct submission establishes that the submitted key matches this instance and was received within its round. The site checks the answer and records the accompanying method and resources. It does not independently verify the declared computation or reproduce the method.
            
      
            
      
              An incorrect answer locks that instance. An expired instance without an accepted recovery is simply unsolved here; it is not evidence of a security bound. A challenge tier selects a scheme-specific parameter set, not an estimate of security bits.
            
      
            
      
              This challenge records practical recoveries. It does not yet accept or verify asymptotic attack proofs.
            
      
          
      
          
      
            
              Submission and ranking rules
              
                +
              
            
            
      
              Each account gets one private instance per profile per round, and one well-formed answer for that instance. Submit the complete shared key, a reusable method version, and a compute declaration.
            
      
            
      
              Method versions are immutable. Correct recoveries can appear publicly with the account handle, method, pseudocode, and compute declaration. Each tier highlights the earliest accepted recovery at that tier or higher, across all rounds. Other results remain on participant profiles. Different profiles are not ranked against one another.
