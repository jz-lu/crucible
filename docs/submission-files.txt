CRUCIBLE — RECOVERED-KEY RESULT FILES (VERSION 1)

Purpose

A JSON file can fill every field of a recovered-key submission. It can be written
by hand, generated by a solver, or prepared with an AI assistant. Importing the
file does not submit an answer: review the populated form and select Submit.

In the current challenge, open Submit recovered key and choose Download template.
The template includes this exact challenge_id. Fill its empty values, save it as
UTF-8 JSON, and choose Upload result file. The maximum file size is 128 KiB.
Do not include Markdown fences, comments, passwords, session tokens, or private
long-term keys. candidate is the recovered encapsulated shared key.

Contract

{
  "format": "crucible-recovery-v1",
  "challenge_id": "copy the exact identifier from your template",
  "candidate": "replace with the complete recovered key in hexadecimal",
  "method": {
    "name": "A short descriptive name",
    "pseudocode": "Describe the algorithm, key derivation, and preparation."
  },
  "compute": {
    "hardware": "Describe the CPU/GPU model and configuration used",
    "workers": 1,
    "wall_seconds": 2.5,
    "precomputation": "Describe preparation and its cost, or None",
    "peak_memory": "Estimate with units, or Not measured",
    "notes": "Optional measurement details and uncertainty"
  }
}

The example contains placeholders; replace them with the actual result. A blank
downloaded template is deliberately incomplete and cannot be imported as a valid
answer. Keep challenge_id unchanged. In a downloaded challenge contract, the ID
is challenge.id, and the shared-key length is declared by the stored manifest and
challenge.public.encoding.shared_secret_bytes.

Rules

- Only the listed fields are accepted. All fields are required except compute.notes.
- format must be exactly crucible-recovery-v1.
- challenge_id must identify the current instance, including its account and round.
- candidate contains exactly twice the declared shared-key byte count in hexadecimal
  characters, with no spaces or 0x prefix. Uppercase hex is accepted and normalized.
- method.name: nonblank text, at most 100 characters.
- method.pseudocode: nonblank text, at most 15,000 characters; use \n for line breaks.
- compute.hardware: nonblank text, at most 500 characters.
- compute.workers: a JSON integer from 1 through 1,000,000, not a quoted number.
- compute.wall_seconds: a finite JSON number from 0 through 315,576,000, in seconds.
- compute.precomputation: nonblank text, at most 2,000 characters.
- compute.peak_memory: nonblank text with units or an explicit uncertainty statement,
  at most 300 characters.
- compute.notes: optional text, at most 2,000 characters; omitted means empty.

The browser checks the entire file before changing the draft. An invalid file
leaves existing entries intact. Importing does not consume an attempt. The server
still enforces account ownership, the exact shared-key length, one final answer,
and receipt before the shared hourly deadline. Importing cannot extend that time.
Method and compute declarations remain contributor-reported, whether typed or
uploaded. Pseudocode is stored as text and is not executed by the website.

Automation and the existing HTTP API

The upload maps to the same API calls as manual entry:
1. POST /api/methods with the file's method object; retain the returned method.id.
2. POST /api/challenges/{challenge_id}/submit with candidate, that method_id,
   compute, and a freshly generated UUID idempotency_key.

Retain the exact submission body and idempotency_key for retries. Do not create a
different answer or retry identifier when the outcome of a request is unknown.
Clients must authenticate using the current session-cookie flow and send the
X-CSRF-Token and an allowed Origin on writes; see docs/architecture.txt. The file
is an import format, not a new unauthenticated upload endpoint. It deliberately
contains no credentials or persisted browser state.

A dedicated token-based client API and richer automation are future work. The
versioned file structure provides a stable starting point without changing the
existing numerical submission rules.
