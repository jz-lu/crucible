Real-browser quality gate
=========================

The fast standalone Node tests remain the detailed state-machine regression
suite. The required Chromium job adds actual script loading, CSS/shadow DOM,
layout, focus, native dialogs and HTTP behavior. It runs once, not once for each
Python version. Failed tests are not retried or skipped.

The browser job uses ubuntu-24.04, matching the native release job's runner.
GitHub began moving ubuntu-latest to Ubuntu 26.04 in October 2026; slow dependency
downloads on that image consumed most of the browser job's 12-minute budget.
Pinning the tested distro avoids an implicit OS change, but does not guarantee
fast package mirrors. Playwright, Chromium, the 12-minute limit, retries and
required CI gate remain unchanged. GitHub's migration guidance explicitly offers
this pin: https://github.com/actions/runner-images/issues/14748

Run from the repository with the existing Python dependencies installed:

  npm ci --prefix tests/browser --ignore-scripts --no-audit --no-fund
  cd tests/browser
  npx --no-install playwright install --with-deps chromium
  npm test
  npx --no-install playwright test --config participant.config.cjs
  npx --no-install playwright test --config points.config.cjs

Playwright 1.62.1 and its transitive packages are pinned in package-lock.json.
They are development-only dependencies. CI installs the matching browser. For a
local existing Chromium, CRUCIBLE_BROWSER_EXECUTABLE may name its executable;
CRUCIBLE_BROWSER_PYTHON may name the Python interpreter with requirements.lock
installed. Neither option changes the fixed loopback origin or accepts a hosted
target. The runner refuses to reuse an existing server on port 8029.

The separate points.config.cjs command uses port 8030 and points_server.py,
preserving an already running local preview on port 8029. Its temporary SQLite
database and portable DH7/RSA4 catalogue run the real submission/review/rating
and operator-credit handlers, checking profiles and ranking at 31 stages before
serving the actual UI. It does not inject points or replace API responses.
Registered RSA source stands in for a new-family admission only inside the empty
synthetic ledger; this verifies the gates, not scientific novelty. The browser
checks desktop/mobile totals and all four breakdown categories, then completes
an additional real bounty and verifies that an open Leaderboard refreshes exactly
once. Week boundaries use a consistent test clock, without changing the OS clock.
The synthetic evidence is written to .local/points-rehearsal-evidence.json.
Both servers refuse to reuse their own fixed port and delete their temporary
databases on exit. The points command is a separate required browser-job step.

server.py creates an ephemeral SQLite database, random test application key and
synthetic accounts/notes. It passes explicit Settings, never loads an .env or
opens the operator's database, and binds only 127.0.0.1. The actual application
serves the real checked-out web assets and enforces session/membership rules.
Only the fixture subprocess limits the registry to portable DH release 4 and
its declared record-comparison releases 2 and 3, using the established portable
authentication-test pattern. Production registration, artifact verification and
database schema are unchanged. The ordinary navigation journey issues a small
synthetic DH instance and downloads its inputs. The separate participant journey
uses a fresh fixture server/database: it downloads public inputs, runs the existing
toy DH solver on exactly that JSON, submits the recovered key through the actual
form, and opens its saved receipt. Its compute report is explicitly synthetic,
not benchmark evidence. This run is isolated because an accepted recovery changes
the scheme-wide record; it must not contaminate the other tests' unsolved fixtures.
Mail is disabled. GitHub's external identity exchange is replaced only inside
the test fixture; a browser test intercepts the provider navigation and returns
to the real local callback. State, binding, session rotation and page loading
run through the real application. No request reaches GitHub. Other browser
requests outside this loopback origin fail.

The checks cover cached navigation while a real response is held, brand
navigation without a document reload, anonymous/revoked private reads, a late
private response across an account change, concurrent map asset requests without
duplicate CSS, rendered SVG and keyboard dialog behavior, mobile note layout and
focus, neutral initial-access/route previews while real responses are held, and
successful GitHub return without a redundant continuation request, a usable
landing page while unused math assets are absent and subsequent equation
hydration, and real stalled notebook/map script deadlines followed by retry while
the original requests remain stalled. Controlled response
holds establish ordering; no sub-100ms timing threshold depends on runner load.
The stalled-script case intentionally waits for the real 15-second deadline.

Cold and prepared journeys have explicit, separate preconditions. Register
interceptors and response observers before sign-in can start idle preparation.
Some cold-layout and paginated-fallback cases explicitly use the browser's
Save-Data preference to suppress optional reads; they still use real foreground
requests and session checks. This is not the default fixture. Dedicated normal-
preference cases verify actual background summaries, local filters, first People
and submission visits, Timeline reuse and account invalidation. Do not assume
an admitted page stays cold, or disable preparation globally to hide a race.

Additional journeys exercise Notes filters with out-of-order responses, retained
rows, cached Timeline validation, revocation, interrupted API bodies, repeated
reloads, image decoding and late bootstrap, fully styled pages with the old
external main-CSS endpoint blocked, Record-to-Challenge
focus, manual download/submission controls, and maximum-length mobile tags. The
logo streaming check holds actual image bytes; response classification checks
use synthetic transport failures. Neither establishes a particular hosted cause.
Main-style checks verify the exact embedded stylesheet hash, one effective CSP
header, early deferred-script discovery, and public/admitted layouts after reload.
Record-page checks hold leaderboard and submission-list responses to compare
their initial and settled geometry on desktop and mobile. They also cover cached
revisits, long/empty histories, nested-dialog focus, and late/denied responses.
Synthetic submission rows used for layout checks replace only an already
authorized fixture response; they do not create accepted cryptanalytic results.
Cold route checks independently hold bootstrap, app and session responses: only
public neutral geometry is available initially, then the destination's frame,
with no protected requests before admission. Returning signed-out gate geometry
is tested separately from admitted catalogue reloads. Timeline checks compare
the held aggregate frame with the actual curve and preserve scroll when changing
views. Keyboard focus, late response and revoked-session checks remain required.

Failures retain synthetic screenshots and traces for seven days in CI. They
contain disposable fixture credentials and notes, never participant information.
There is no production URL, provider credential, database connection or login in
this suite. Tests and browser packages are not included in the release image.

For a person reviewing the local UI, start the disposable server:

  .venv/bin/python -B tests/browser/server.py

The UI is the same as the deployed application, including Continue with GitHub.
This fixture has a synthetic OAuth client, so real GitHub authorization cannot
complete here. Automated tests intercept only the provider exchange and exercise
the application's state, binding, session and invitation checks. Real GitHub
sign-in requires a configured OAuth application and matching callback URL; there
is no local provider screen or alternate navigation allowance. Password sign-in
is available with browser_alice / Synthetic browser fixture password. This server
uses disposable data and never connects to hosted accounts or the hosted database.
The fixture enables the existing local mail transport. Its startup output gives
the outbox directory; invitation.json there contains a fresh seven-day invitation
for preview@example.invalid. Verification messages are ordinary .eml files in the
same directory, with real, account-bound test codes. Set CRUCIBLE_BROWSER_OUTBOX
to choose a private directory. The signup suite completes mailbox verification
with a separate fixture invitation, leaving the manual invitation unused.
Links belong to the database/site that issued them: a production invitation
pasted into localhost gets a clear site-mismatch message rather than a syntax
error. Use a local invitation for a local preview.

Landing comparisons use /#home?layout=centered and /#home?layout=left. The
landing-variants suite checks the actual alignment of brand, tagline, beta label,
description and actions on desktop/mobile in both themes. It captures both
compositions, verifies the absence of header/card borders and horizontal overflow,
and checks that the sign-in dialog and focus return still work.

Scope: Chromium at desktop and mobile viewport sizes, real ASGI/SQLite HTTP and
browser behavior. This is not hosted performance/capacity evidence, a complete
accessibility audit, native cryptographic verification or PostgreSQL integration.
The separate source security tests and reviewed native-image release checks
remain required. Manual keyboard, screen-reader and cross-browser review still
matter; this small gate is a repeatable foundation rather than a completeness claim.
