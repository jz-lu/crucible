Crucible research-tier expansion — decision record
=================================================
2026-10-14. Local research beta; independent scientific admission is separate.

Mission and constraints
-----------------------
Keep at most10 visible scheme families, meaningful distinct attack surfaces,
low navigation cost, actual mathematical parameters and machine-readable exact
contracts. Preserve accounts/history and make automation convenient. A tier is
not evidence of security. A recovered individual secret is not an IND-CCA break
or a statement about every other instance. Never manufacture correctness from
passing samples or artificially restrict secret entropy to create easy levels.

Why these ladders differ
-----------------------
1. EC: X25519 is fixed-size. Bounded exponents would quietly change the secret
   distribution, so we instead generate ordinary prime-order curves with full
   nonzero scalars and a separately specified full-point KDF. All constants have
   exact public primality/group-order proofs. A generic rho reference is useful
   but is not a full security analysis. The endpoint is not Curve25519.

2. Frodo: changing the matrix dimension retains the core plain-LWE problem,
   full noise distribution, message, salt and seed lengths. The640 endpoint is
   byte-conformant to current salted Frodo640. The entire ladder has a conservative
   analytical agreement-failure bound2^-133 in the declared ideal-XOF model;
   the smallest profile additionally has a deterministic zero-failure argument.
   The pinned estimator is unreliable at its small block-size floor, so the
   smallest costs are left unknown rather than invented.

3. Module lattices: naively shrinking polynomial degree loses message capacity;
   changing ciphertext compression without a new bound is unjustified. This
   explicit lossless module-LWE derivative retains full256-bit messages and CBD2
   noise. Its moduli make the worst-case noise smaller than the decoding margin.
   It differs from FIPS203 in parameters, matrix sampling and wire encoding and
   does not inherit an ML-KEM security theorem. Larger easy-tier moduli can mean
   larger keys: graphs report that real tradeoff, not a forced monotone size curve.
   Tier1 uses module rank1; tiers2–50 use rank3. The smallest modulus is47339;
   the final model value is127.978777 reference bits, not relabelled128. First
   profiles affected by the estimator floor have no asserted numerical value.
   Bounded attempts at a public-only first-tier LLL recovery did not complete;
   the example solver remains experimental, with no validated solve-time claim.

4. NTRU Prime: exact algebraic admissibility and perfect-correctness inequalities
   support a degree ladder with real smaller rings. All50 tuples are certified.
   The endpoint agrees with original sntrup761 vectors; the full uniform sampler
   is explicitly distinguished from the old reference's near-uniform maps.
   Degree order is not a measured attack-cost order. Search-space enumeration is
   published separately, never presented as estimated security.

5. HQC: keeping the established ring and decoder while varying weights permits
   a transparent worst-case correctness proof through weight27. Extending to50
   would leave that proof's domain. Fewer justified levels are preferable to
   fabricated duplicates or an inherited tiny failure probability. These are
   low-weight research targets, not a ladder ending at a published128-bit claim.

6. McEliece: retain the field/Goppa degree/decoder and vary code length within
   the published general-parameter construction. Use its exact variable sampling
   batch rule. Actual elementary Prange trial counts guide parameter spacing;
   they exclude elimination work, improved decoding and structural attacks and
   therefore are not labelled security bits or normalized to128.

Evidence and operational choices
--------------------------------
Correctness has three layers: an analytical statement with declared scope;
independent arithmetic/conformance tests; and one honest agreement check for
each runtime draw. The latter never validates a rare-failure bound by itself.
Encaps' original secret is always the target. A disagreement is recorded and
the profile held; no resampling until a convenient success or replacement with
Decaps' output. Process aborts and discarded draws remain in the outcome ledger.
Public reports expose aggregate counts without participant identity or secrets.

The source wrapper, parameter data, helper code and relevant native build are
pinned as a complete artifact closure. The CLI verifies that closure and fetches
declared first-party source/parameters into reference/source/. It never executes
downloaded reference code automatically, installs native dependencies or runs
participant code on the service. Local native workers have fixed allowed
operations, output bounds and deadlines. No arbitrary decapsulation oracle.

Uncalibrated research releases use exact-profile recovery records: solving one
does not backfill another. Milestone badges follow the same rule. The existing
DH/RSA recognition convention stays, and the EC generic progression explicitly
uses it as a display convention rather than an assertion of individual solves.
Research releases were initially excluded from global point scoring. On
2026-10-14 the user explicitly requested their enrollment; points policy v3
includes the six frozen research releases with the existing provisional weights.
Exact-profile recovery rules remain unchanged. Equal points are participation
incentives, not equal measured attack difficulty. No proposal/admission points
are created by adding these known reference families.

Independent manual admission and production operation remain separate from
user-authorized local-beta availability. Do not represent these implementation
checks as an independent cryptographic audit. Current native pins are macOS
arm64-specific; see native-setup.txt before another deployment.
