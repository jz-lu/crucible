Purpose

Merge the accepted assumptions prototype into the existing application, keeping
its notebook, accounts, immutable revisions, publication controls, citations,
resource reports, routing and theme. No separate assumptions application or
synthetic security curve is installed.

What is implemented

- Optional content.sections [{id,title,body}] provides a flexible readable companion.
  The existing body remains the complete Full text. Both are hashed, saved,
  exported, screened and permission-checked in the same immutable revision.
- Sections have stable identifiers, exact-revision citation links and safe local
  Markdown/KaTeX rendering. Existing body-line citations continue to work.
- The editor adds/removes sections without deriving their IDs from changing
  titles. Existing notes/hashes remain unchanged when sections are absent.
- A small shared graph interaction module provides a hover dot/halo and a
  committed dot and dashed guide across the existing resource/security renderers.
  Selection is release/profile scoped; absent values remain absent.
- Eight sourced readable notes cover current scheme releases. Their 46 sections
  explain security, correctness, attack references and 10 scoped unproved/model
  premises. Nine scheme-security gaps remain separate prose, not assumptions.
  Sources and original evidence revisions are
  pinned; stronger newer results are distinguished from retained older text.
- Separate Security and Correctness entries each open their own premise list. Explicit authored
  scheme_assumptions membership selects exact, titled premise sections; the same
  premise can serve both contexts. Missing category metadata is unknown, while
  missing security arguments are labelled separately from numbered premises.
  Each category also links to its exact justification section. A committed attack point
  exposes its exact attack section and only the bound applicable premise links.
  The specification link is present even with no numbered assumptions. Badges
  sort numerically; existing premise identifiers survive edits and retirement.
  Missing KEM arguments cannot be bound as an attack premise. The attack is not
  responsible for establishing the KEM's security, or excluding faster attacks.
  No plot value is invented, interpolated across a gap, or changed by a note.

Local isolation and reproduction

The development-only CRUCIBLE_LOCAL_NOTE_CORPUS_ONLY=true suppresses the packaged
legacy notebook and its old display links. It cannot be enabled in production.
Use a fresh explicit CRUCIBLE_DATA_DIR, run the normal database migrations, then:

  python scripts/prepare_note_integration.py --data-dir PATH_TO_FRESH_LOCAL_DATA

The builder refuses an occupied unrelated notebook, validates every source pin,
creates notes via the normal API, requests publication and records a clearly
labelled local fixture publication decision through the normal reviewer API.
This decision is not independent scientific review or scheme admission. It makes
no provider calls and deletes no notes/accounts. The same completed fixture is
not duplicated on rerun. Changed source requires an explicit new fixture or
--revise-fixture, which validates the existing identities and writes ordinary
immutable note revisions. --check performs the preflight without writes. The
builder refuses independent edits and does not overwrite history.

The explicit local scheme-note-bindings.json pins one exact note revision and
its security/correctness/attack sections for each exact release. The API checks
visibility, hashes, section existence, scheme context, graph model identity and
profile scope before returning links. This local binding manifest is a preview
of display adoption, not a production adoption/review store.

Further work before hosting

- Agree the display/adoption review for binding an exact published note to a
  live scheme/attack. Publishing a note alone must never alter scheme state.
- Persistent cross-note assumption identities, version succession, scoped
  challenges/refutations and adoption history need their own narrow design.
  Current labels are authored objects in exact notes, not certified verdicts.
- Extend proposal admission to require exact justification-section references
  without rewriting older approved proposals or treating links as proof.
- Review the eight authored explanations scientifically; the present pass checks
  attribution, scope and source consistency, not independent mathematical proof.
- Preserve old/new note-reader compatibility during any eventual deployment.
  This JSON extension requires no database migration, but older clients will
  not present readable sections and must not silently discard them on edits.
