MODULE-LATTICE v4 DESIGN — 17 OCTOBER 2026

Identity: ml-kem / compressed-research-v4.
Implementation: crucible/lattice_module_v4.py and module_compressed_v4_core.py.

Why this path

Use the published ML-KEM-512 tuple as the endpoint: q=3329, rank 2, eta1=3,
eta2=2, du=10, dv=4, with degree 256. Hold all those settings except degree fixed,
and take the six power-of-two degrees 8,16,32,64,128,256. This retains a simple
structural relationship to the endpoint while making the transmitted objects
and arithmetic smaller at earlier configurations. It is a restricted design
choice, not a proof of global parameter or performance optimality.

Six natural settings are preferable to artificial intermediate settings added
to meet a cosmetic tier count. A tier is an ordinal configuration selector,
not a security-bit estimate. No cross-scheme equality of tiers is implied.
ML-KEM-768 is not a separate selected deployment or comparison reference.

The endpoint uses FIPS 203 algorithms, transforms and encodings for completed
operations. Independent NIST ACVP vectors check key generation, encapsulation,
decapsulation and key validation; this is conformance evidence, not FIPS
certification. The bounded reference sampler and isolated generator may abort
for resource reasons; these outcomes are separately accounted for.

Lower degrees are nonstandard research constructions. They use a generalized
incomplete NTT, the full native n-bit message space and explicit parameter/purpose
hash separation. The smaller rings have different factorization structure and
may admit additional attacks. They inherit neither the endpoint's NIST category 1
assessment nor a full-KEM security guarantee. No uncalibrated attack-cost curve
is fabricated. Generic enumeration of native messages remains an explicit attack
route. The 32-byte output format does not establish 256-bit security.

  4      64    224 bytes   192 bytes  <=2^-193: conservative analytical bound
  5     128    416 bytes   384 bytes  <=2^-236: explicit compression model
  6     256    800 bytes   768 bytes  <=2^-128: explicit compression model

Sizes count actual encoded bytes, excluding JSON/hex transport. The public key
has 3n+32 bytes and ciphertext 3n bytes. All profiles return a 32-byte shared key.
The old module-v3 source, parameters and receipts retain their old meaning;
this new release does not relabel them or reuse their benchmarks.

Common correctness requirement and margins

Every configuration must meet the common <=2^-128 honest-agreement ceiling
under its reviewed premises. This is an upper bound, not an identical failure
rate. Zero is allowed where naturally proved; it is no longer imposed on every
configuration. The old q=24593 endpoint enlarged the modulus to cover worst-case
noise support. That extra size did not establish stronger security.

For v4, exact integer rounding gives |delta_u|<=2 and |delta_v|<=104. An honest
decoding error requires an integer residual of absolute value at least 832.
After allowing worst-case v rounding, the analyzed remaining tail starts at 728.
For degrees 8/16, the full residual support is at most 21*rank*n+106<832.
For degrees 32/64, the proof uses independent expanded CBD noise but leaves
u-rounding dependent and bounds it conservatively. It does not assume uniform
compression errors. For degrees 128/256, the reported target additionally models
u-rounding errors as independent errors from uniform coefficients, independent
of the relevant secrets and noise. v-rounding remains worst-case bounded.

Exact rational Chernoff and union calculations prove the bound within that
specified experiment. They do not prove the model's applicability to fixed
SHA3/SHAKE executions. The endpoint's computed exponent is approximately
128.041429812; an integer comparison certifies the conservative 2^-128 ceiling.
The published ML-KEM-512 estimate is approximately 2^-138.8 under its published
analysis. We retain this distinction and do not copy it to reduced degrees.

Failure means a mismatch or honest rejection in one fresh honest exchange,
averaged over the specified key and encapsulation randomness. This is not a
worst-key or adaptive IND-CCA correctness statement. Generation aborts are
separate; disagreement is retained and quarantined, never silently retried.
Implementation and model acceptance remain manual review obligations.
