Intent

The scheme page opens a Security argument or Correctness argument. An argument
states the claim and scope, then shows its assumptions and an exact note link.
The note is the research record; there is no separate assumption-writing portal.

Reading

Read argument opens the exact argument in the ordinary note reader. If the note
has a readable reasoning section, that section appears with the argument once.
Other arguments and the statement list stay folded until requested. Assumption
links open the precise statement definition in that same versioned system.
Full text is always available. Notes without a readable companion still say so
and keep Full text collapsed, except for a direct citation to a full-text passage.

Authoring

Optional statements hold precise definitions. Optional arguments contain a
conclusion, scope, authored status, reasoning location and exact premise uses.
An assumption is a statement's role in that argument, not a global truth label.
Most ordinary notes need neither structure. The existing title, summary, scope,
full-text and citation fields remain compatible; this pass does not redesign
the general note API or introduce a document block editor.

A premise use can have one explanation, “How this premise is used”, rather than
three mandatory prose fields. If omitted, the whole exact proposition is used
as written in the argument scope. Omission proves no parameter mapping or
implication. Historical required/mapping/justification records remain readable
and unchanged. Mixing the old and new explanations is rejected.

Evolution

An edit creates a new note revision. Earlier references still resolve to their
original text and hash. A challenging note is evidence, not an automatic verdict.
The local reviewed-selection trial can select or withdraw an exact argument for
a fixed result. Withdrawn uses appear as previous uses. Empty dependency lists
never automatically mean unconditional correctness; completeness is authored
and still needs examination. Incomplete arguments are visibly marked.

Publication and scientific adoption are separate. These local scheme display
bindings are explicit fixture selections, not independently reviewed adoptions.
The eight converted scheme notes preserve their scientific limitations and
numeric attack accounts. The conversion does not prove their mathematics,
establish best-known attacks or turn attack upper bounds into security bounds.

Compatibility and remaining work

Current scheme presentations read canonical arguments and statements. Historical
scheme extension metadata has a read-only adapter to the same display contract;
old revisions and citations are not rewritten. The generator still accepts its
previous scientific source format as input, with an explicit conversion record.

The local adoption workflow remains a rehearsal, separate from the hosted
proposal application mechanism. Integrating actual scheme presentation slots,
the production dependency index and a hosted migration/release remains future
work. The current update form requires an explicit target; it never silently
selects an unrelated demonstration result.
