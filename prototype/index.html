Toy DH-KEM

A small-group teaching example based on Diffie–Hellman.

ChallengeRecover the full shared key

Time windowOne hour from release
What is being tested? +

Given a fresh public key and encapsulation, recover the complete encapsulated shared secret. Submit it within one hour of the site releasing your challenge. The shared secret and generation randomness are kept private; no candidate key is supplied.

This teaching construction uses a deliberately small cyclic group. Its public key is gˣ; an encapsulation is gʳ; its shared key is KDF(encode(gˣʳ)), using a fixed, unambiguous encoding. There is no decapsulation oracle in this example. This is not a production scheme or a proposed security benchmark.

In a live submission, the method is contributor-reported. Independent reproduction provides additional evidence.

The idea

Make the evidence useful.

A shared research record for proposed key encapsulation mechanisms.

  1. 01

    Receive a fresh challenge

    Receive a fresh public key and encapsulation specific to your attempt. The one-hour clock starts when the site releases them.

  2. 02

    Investigate on your own hardware

    Recover the complete shared secret using your tools and resources. One hour is the response window; it does not limit total compute.

  3. 03

    Share the result and the method

    Submit the complete key, pseudocode, and estimated compute. The site checks the key and deadline. One verified recovery records an instance solved.

This is a first interface draft.

One teaching scheme, one illustrative entry, and a local contribution form. The challenge service and final scheme catalogue are still to be designed. This version records recovery; distinguishing attacks can be added later.
